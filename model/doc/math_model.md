# FMA 数学建模 — 从零开始理解融合乘加

> 本文写给大一新生：只要会加减乘除和一点点二进制，就能看懂。

---

## 第一章 什么是 FMA？

### 1.1 先看一个简单的算式

```
结果 = A × B + C
```

比如：
- A=2, B=3, C=4 → 结果 = 2×3+4 = **10**
- A=1.5, B=2.0, C=0.5 → 结果 = 1.5×2.0+0.5 = **3.5**

这就是 FMA（**F**used **M**ultiply-**A**dd，融合乘加）——**一次完成乘法和加法**。

### 1.2 为什么要"融合"？

普通做法分两步：
```
第1步: temp = A × B    (乘法)
第2步: result = temp + C  (加法)
```
问题：每一步都要**四舍五入**，两次舍入误差叠加。

FMA 的做法：
```
第1步: 计算 A×B 的精确值（不四舍五入！）
第2步: 把这个精确值加 C（不四舍五入！）
第3步: 只对最终结果四舍五入一次
```

**结论：FMA 比分开算更精确。** 就像你先算账再开发票，比每笔都开发票更准。

## 第二章 二进制与浮点数

### 2.1 整数在计算机里怎么存？

十进制整数用二进制表示：

| 十进制 | 二进制 |
|--------|--------|
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 5 | 101 |
| 10 | 1010 |
| 255 | 11111111 |

> 练习：十进制的 13 转二进制是多少？答案是 1101

### 2.2 小数怎么办？—— 科学计数法

十进制中：`123.45 = 1.2345 × 10²`

二进制中也是一样：`101.11 = 1.0111 × 2²`

科学计数法的三要素：
- **符号**：正还是负（+ 或 -）
- **指数**：2 的多少次方（上面的 "²"）
- **尾数**：小数点后面的部分（上面的 "0111"）

### 2.3 IEEE 754 浮点数的结构

计算机用三个字段存储浮点数：

```
┌──────┬──────────┬─────────────────────┐
│ sign │ exponent │      mantissa       │
│ 符号 │   指数   │       尾数          │
│ 1bit │   e bits │       m bits        │
└──────┴──────────┴─────────────────────┘
```

不同精度的位数分配：

| 格式 | 总位数 | 符号 | 指数 | 尾数 | 类比 |
|------|--------|------|------|------|------|
| FP32 | 32 bit | 1 | 8 | 23 | 计算器精度 |
| FP16 | 16 bit | 1 | 5 | 10 | 游戏精度 |
| FP8 | 8 bit | 1 | 4 | 3 | 粗略估计 |

> 位数越多 → 越精确 → 但占空间大、算得慢

### 2.4 浮点数怎么算数值？

```
value = (-1)^sign × (1.mantissa) × 2^(exponent - bias)
```

其中 bias 是一个偏移量：
- FP32: bias = 127
- FP16: bias = 15
- FP8: bias = 7

**举例**：FP16 格式，bit 模式 `0 01111 0100000000`

```
sign = 0 (正数)
exponent = 01111 = 15
mantissa = 0100000000 = 0.25 (二进制小数 0.01)

value = (+1) × (1 + 0.25) × 2^(15-15)
      = 1.25 × 2^0
      = 1.25
```

> 练习：FP16 的 `1 10000 0000000000` 代表多少？答案是 -2.0

## 第三章 FMA 的计算过程（逐步拆解）

以 FP32 为例，计算 `A × B + C`：

### 第 1 步：乘法 —— 符号

```
结果的符号 = A的符号 ⊕ B的符号  (⊕ 表示异或：同性得正，异性得负)
```

其实就是：正×正=正、负×负=正、正×负=负、负×正=负

### 第 2 步：乘法 —— 指数

```
乘积的指数 = A的指数 + B的指数 - bias
```

例如 A 的指数=5, B 的指数=3, bias=127：
```
乘积指数 = 5 + 3 - 127 = -119
```

### 第 3 步：乘法 —— 尾数

A 的尾数 (1.a) 和 B 的尾数 (1.b) 相乘，得到 24+24=48 位的精确乘积。

这就是 FMA 的"秘密武器"——保留了乘法的全部精度。

### 第 4 步：对齐 —— 把 C 对齐到乘积

因为指数不同，不能直接相加。需要把小指数的数右移，让两个数的指数一致。

就像：`3.0 × 10² + 1.5 × 10¹`
= `3.0 × 10² + 0.15 × 10²`（把 C 右移对齐）
= `3.15 × 10²`

### 第 5 步：相加

用进位保存加法器 (CSA) 把乘积和 C 加起来，得到 50 位的精确和。

### 第 6 步：规格化

把结果调整成 `1.xxx × 2^e` 的标准格式。

例如 `0.00101 × 2^5` → `1.01 × 2^2`（左移3位，指数减3）

### 第 7 步：舍入

50 位结果要压缩到 23 位（FP32 的尾数宽度）。舍入规则是 **RNE（Round to Nearest Even，就近舍入到偶数）**：
- 如果丢掉的部分 < 0.5，舍去
- 如果丢掉的部分 > 0.5，进位
- 如果恰好 = 0.5，看保留的最后一位：是 0 就舍去，是 1 就进位

## 第四章 特殊值处理

### 4.1 零 (Zero)

指数全 0，尾数全 0。有 +0 和 -0 之分，但数值上相等。

```
0 × 任何数 + 0 = 0
```

### 4.2 无穷大 (Infinity)

指数全 1，尾数全 0。

```
1.0 × Infinity + 0 = Infinity
0.0 × Infinity + 0 = NaN  ← 注意！0×∞ 没有意义，返回 NaN
```

### 4.3 非数 (NaN, Not a Number)

指数全 1，尾数非 0。

```
NaN × 任何数 + 任何数 = NaN
```

NaN 就像数学中的"无意义"——任何运算遇到 NaN，结果都是 NaN。

### 4.4 特殊值判定表

| A | B | C | 结果 |
|---|---|------|------|
| NaN | x | x | NaN（传播） |
| 0 | ∞ | x | NaN（无效运算） |
| 正常 | 正常 | NaN | NaN |
| 正常 | 正常 | 正常 | 正常计算 |

## 第五章 多精度模式

本项目的 FMA 支持 6 种运算模式，由 `mode[2:0]` 信号选择：

| mode | 模式 | 输入精度 | 输出精度 | 用途举例 |
|------|------|----------|----------|----------|
| 000 | FP32 FMA | 32-bit | 32-bit | 科学计算 |
| 001 | FP16 FMA | 16-bit | 16-bit | 图形渲染 |
| 010 | FP8×4 FMA | 8-bit×4 路 | 32-bit 打包 | AI 推理 |
| 011 | INT8 MAD | 8-bit 整数 | 16-bit | 深度学习 |
| 100 | FP16→FP32 Acc | 16-bit 乘 | 32-bit 累加 | 混合精度训练 |
| 101 | FP8×4→FP32 Acc | 8-bit×4 乘 | 32-bit 累加 | AI 训练加速 |

## 第六章 误差分析

FMA 的最大优势在于**只有一次舍入**。

### 普通做法（两步，两次舍入）：
```
精确值 = A×B + C
计算值 = round(round(A×B) + C)
误差 = 计算值 - 精确值   ← 最多可能是 2 个 ULP
```

### FMA 做法（一步，一次舍入）：
```
精确值 = A×B + C
计算值 = round(A×B + C)
误差 = 计算值 - 精确值   ← 最多 0.5 个 ULP
```

> **ULP** = Unit in the Last Place = 最低有效位的值  
> 0.5 ULP 意味着"最大误差不超过最后一位的一半"

### 数值举例

A=1.0000001, B=1.0000001, C=-1.0

```
精确值: 1.00000020000001 - 1.0 = 0.00000020000001
普通做法: round(1.0000002) - 1.0 = 1.0000002 - 1.0 = 0.0000002 (一次舍入)
　　　　　但 round(1.0000002) 已经损失了精度
FMA做法: round(1.00000020000001 - 1.0) = round(0.00000020000001) = 0.0000002
```

虽然这个例子看起来差不多，但在大量运算中，FMA 的累积误差远小于普通做法。

## 第七章 3 级流水线

硬件不是一步算出结果，而是分成 3 个阶段，像流水线一样：

```
时钟周期 →  Stage1    Stage2    Stage3
          ┌───────┐ ┌───────┐ ┌────────┐
A×B+C →  │ 乘法  │→│对齐加│→│规格化舍入│→ result
          │ 24×24 │ │CSA 50b│ │LZC+移位 │
          └───────┘ └───────┘ └────────┘
```

第 N 个计算进入 Stage1 时，第 N-1 个在 Stage2，第 N-2 个在 Stage3。
这就是"流水线"——每个时钟周期都能输出一个结果（延迟 3 个周期）。
